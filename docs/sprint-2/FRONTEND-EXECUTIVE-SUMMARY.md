## Key User Stories

### Security Analyst
> "As a security analyst, I want to see which assets are affected by CVE-2024-1234 so that I can assess blast radius within 30 seconds of a new vulnerability announcement."

**Solution:** F.6 — Vulnerability detail page with affected assets table, filter, links to patches.

---

### Patch Manager
> "As a patch manager with 200+ recommendations, I want to accept all critical-severity recommendations at once so that I can process approvals in 2 minutes vs 30 minutes."

**Solution:** F.13 — Bulk accept/reject with multi-select, confirmation modal, single API call.

---

### IT Administrator
> "As an IT administrator with slow internet, I want the application to load quickly so that I can start working within 2-3 seconds."

**Solution:** F.3 — Lazy loading reduces initial bundle from 500KB to <150KB, FCP <1.5s.

---

### Compliance Officer
> "As a compliance officer, I want to see patch supersedence relationships so that I deploy the latest cumulative update instead of outdated individual patches."

**Solution:** F.8 — Supersedence display in patch detail + recommendations list, deployment warning.

---

### Screen Reader User
> "As a screen reader user, I want clear labels on all buttons and inputs so that I understand what each control does."

**Solution:** F.10, F.11, F.12 — ARIA labels, severity indicators with icons, keyboard navigation.

## Risk Assessment

### High Risks
1. **MainLayout refactor takes >3 days**
   - **Impact:** Delays Week 2, cascades to Phase 2
   - **Mitigation:** Time-box to 3 days, ship incremental improvements, use Week 6 buffer

2. **Bulk endpoints not ready from backend**
   - **Impact:** F.13, F.14 blocked (bulk operations)
   - **Mitigation:** Mock in frontend, swap real API when ready, or descope F.14 to P1

3. **Accessibility testing finds >50 violations**
   - **Impact:** Week 4 overruns, delays Phase 3
   - **Mitigation:** Prioritize critical (keyboard, ARIA), defer minor (color tweaks) to P1

### Medium Risks
4. **Security audit scheduled too early (April 1)**
   - **Impact:** Insufficient time for fixes if issues found
   - **Mitigation:** Front-load security work (Week 1), request audit delay to April 15 if needed

5. **Sprint 2 Feature creep (stakeholders add scope)**
   - **Impact:** Timeline extends, deadline missed
   - **Mitigation:** Strict adherence to PRD non-goals, require scope-in = scope-out trades

## Questions for Planning Meeting

### Blocking Questions (Must Answer Before Starting)
1. **Do all 7 required backend API endpoints exist?** (See dependency table above)
   - If no, what's the timeline for backend to add them?
   - Should frontend mock endpoints temporarily?

2. **What is the risk score formula?** (For F.9 tooltip)
   - Is it `(CVSS × 0.4) + (EPSS × 0.3) + (Criticality × 0.2) + (Exploit × 0.1)`?
   - How is asset criticality scored (1-10 scale, High/Medium/Low enum)?

3. **Is security audit date fixed at April 1?**
   - Can it be delayed to April 15 for 2-week buffer post-Sprint 2?
   - What are the audit scope and pass/fail criteria?

### Non-Blocking Questions (Can Resolve During Sprint)
4. **Should bulk deploy allow mixed asset groups?** (For F.14)
   - Example: Deploy KB5034441 to 20 servers (mixed groups) vs "Production Servers" group only
   - Default: Allow mixed, show warning if mixing groups

5. **Is WCAG 2.1 AA sufficient or do we need AAA?** (For F.10-F.12)
   - AA is standard (4.5:1 contrast, keyboard nav)
   - AAA is rare (7:1 contrast, sign language videos)
   - Default: Target AA, document AAA gaps for future

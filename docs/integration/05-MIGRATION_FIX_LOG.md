# Migration Fix Log

**Date:** 2026-01-22
**Issue:** Schema issues needed fixing before migration could be safely applied

## Issues Identified

### 1. AssetSoftwareInventory Missing Relation to Asset
- **Problem:** `AssetSoftwareInventory` model had `assetId` field but no `@relation` directive
- **Impact:** No foreign key constraint, no cascade delete, Prisma relation missing
- **Fix:** Added `asset Asset @relation(fields: [assetId], references: [id], onDelete: Cascade)` to AssetSoftwareInventory and `softwareInventory AssetSoftwareInventory?` to Asset model

### 2. Manual Migration Not Tracked Properly
- **Problem:** Migration `20260122_expand_user_asset_hardware_models` was manually created with custom SQL, not generated by Prisma
- **Impact:** Missing FK constraint for AssetSoftwareInventory, migration format inconsistent
- **Fix:** Removed manual migration folder and regenerated using `prisma migrate dev --create-only`

### 3. Failed Migration: 20260117_add_discovery_module
- **Problem:** Migration failed on shadow database because it tried to ALTER `device_credentials` table that didn't exist
- **Root Cause:** Migration assumed `device_credentials` table existed from a baseline, but no baseline migration was present
- **Fix:** Updated migration to CREATE the `device_credentials` table before the discovery tables

### 4. User Column Rename (name → display_name)
- **Verification:** Searched for raw SQL queries using `queryRaw` or `executeRaw`
- **Result:** NO raw SQL queries found in backend codebase
- **Status:** SAFE - Column rename will not break any raw SQL queries
